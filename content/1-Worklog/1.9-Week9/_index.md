## I. Overview Summary

Following the successful implementation of direct video uploads using Amazon S3 Presigned URLs during the previous week, the team continued developing the core backend components responsible for managing video information throughout the platform. The primary objective of this stage was to establish business APIs, implement a metadata management mechanism, integrate Amazon DynamoDB with backend services, and prepare the infrastructure required for the Event-Driven Video Processing Pipeline that would be introduced in the following week.

Throughout this week, the team developed a collection of RESTful APIs using Amazon API Gateway and AWS Lambda to support business operations such as creating video metadata, retrieving video lists, viewing detailed metadata, and updating processing status. Amazon DynamoDB was selected as the NoSQL database for storing video metadata due to its scalability, high availability, and low-latency performance for serverless applications.

In parallel with backend development, the direct upload workflow based on Amazon S3 Presigned URLs was further refined. Instead of routing large video files through backend services, users upload their files directly to the Amazon S3 Raw Upload Bucket using temporary upload URLs generated by AWS Lambda. This architecture significantly reduces backend workload while improving upload efficiency and lowering operational costs.

The team also standardized the metadata structure stored in Amazon DynamoDB to support future processing activities. Essential attributes such as Video ID, File Name, Upload Time, User ID, Processing Status, Source Object Key, and Output Location were carefully designed to ensure consistency throughout the complete lifecycle of each uploaded video.

By the end of the week, the backend API layer and metadata management system had been fully completed. Users could upload videos directly to Amazon S3 while the platform successfully stored, retrieved, and managed all related metadata, providing a solid foundation for implementing the Event-Driven Processing Pipeline during the following development phase.

## IV. Technical Implementation & In-depth Analysis

After completing the direct video upload mechanism using Amazon S3 Presigned URLs during the previous week, the team concentrated on developing the backend layer responsible for managing business data throughout the Serverless Video-on-Demand Platform. The primary objective of this phase was to standardize communication among the web application, Amazon API Gateway, AWS Lambda, Amazon DynamoDB, and Amazon S3 while preparing the metadata required for the Event-Driven Video Processing Pipeline implemented during the following week.

The first major task involved designing a collection of RESTful APIs using Amazon API Gateway. Individual APIs were organized according to specific business functions, including video creation, metadata retrieval, video listing, processing status updates, and Presigned URL generation. Separating these responsibilities into independent API endpoints simplified future maintenance while allowing new functionality to be introduced without affecting existing services.

Once the API specifications had been finalized, corresponding AWS Lambda functions were implemented to execute the required backend business logic. Each Lambda function was designed with a single responsibility, such as creating new metadata records, retrieving information from Amazon DynamoDB, or generating Presigned URLs for Amazon S3 uploads. This modular implementation follows serverless architectural principles by allowing each function to be developed, tested, and maintained independently.

Amazon DynamoDB was selected as the metadata repository for the platform. A primary key based on **Video ID** was defined to uniquely identify every uploaded video. Additional attributes including file name, upload timestamp, uploader information, processing status, source object location, and processed output location were incorporated into the table design. This flexible schema enables future expansion without requiring structural database modifications.

Whenever a user requests to upload a video, the web application sends a request to Amazon API Gateway to obtain a Presigned URL. AWS Lambda generates the temporary upload URL using the Amazon S3 SDK before returning it to the client. The user then uploads the video directly to the Amazon S3 Raw Upload Bucket without transferring the file through backend services. Simultaneously, the platform creates a metadata record within Amazon DynamoDB with an initial processing status of **Uploaded**, establishing the foundation for the automated processing workflow introduced in the following development stage.

Additional backend APIs were implemented to retrieve video collections and display detailed metadata. Information stored in Amazon DynamoDB is returned as JSON responses through Amazon API Gateway, allowing the web application to display uploaded videos together with relevant information such as upload timestamps, processing status, and uploader identity without requiring direct database access.

Alongside business functionality, IAM roles were carefully configured for every AWS service participating in the backend architecture. AWS Lambda received only the permissions necessary to interact with Amazon S3 and Amazon DynamoDB according to the Principle of Least Privilege. Applying minimal permission policies improved overall platform security while reducing unnecessary access privileges.

Comprehensive testing was conducted after completing the backend implementation. Multiple scenarios were evaluated, including successful uploads, interrupted uploads, metadata retrieval, invalid requests, and repeated API invocations. Testing results confirmed that AWS Lambda functions operated reliably, Amazon DynamoDB consistently stored metadata, and the complete upload workflow behaved according to the intended architecture.

Finally, the backend architecture was reviewed to ensure readiness for the Event-Driven Processing Pipeline scheduled for Week 10. Metadata structures had been standardized, backend APIs were fully operational, and the upload workflow was prepared for integration with Amazon EventBridge, Amazon SQS, EventBridge Pipes, AWS Step Functions, and AWS Elemental MediaConvert.

## V. Infrastructure Challenges, Troubleshooting Log & Professional Insights

One of the primary challenges encountered during backend development involved maintaining consistency between Amazon S3 and Amazon DynamoDB. In certain scenarios, users cancelled uploads before completion, resulting in metadata records existing while the corresponding video files were absent from the Amazon S3 Raw Upload Bucket. To address this issue, the team introduced validation procedures to verify upload completion before allowing subsequent processing stages to proceed, ensuring consistency between storage objects and metadata records.

Another challenge involved configuring IAM permissions for AWS Lambda. Initial permission policies did not provide sufficient access for writing metadata into Amazon DynamoDB or generating Amazon S3 Presigned URLs. After reviewing IAM policies and refining service-specific permissions, all backend functions operated successfully while remaining compliant with the Principle of Least Privilege.

During API testing, additional attention was given to Cross-Origin Resource Sharing (CORS) between the web application and Amazon API Gateway. Several browser requests were initially rejected because required HTTP headers were missing from API responses. Once CORS configurations were completed, all frontend requests successfully communicated with backend services while maintaining appropriate browser security policies.

Throughout the implementation process, the team recognized that separating the upload layer, metadata management layer, and future processing layer provides significant architectural advantages. Independent service responsibilities simplify maintenance, improve scalability, and establish a strong foundation for the Event-Driven Processing Pipeline implemented during the following development phase.

## VII. Strategic Plan for the Following Week

During the following week, the team will implement the **Event-Driven Video Processing Pipeline** to automate the complete video processing workflow after files are uploaded to the Amazon S3 Raw Upload Bucket.

The next development phase will integrate Amazon EventBridge to receive upload events, Amazon SQS to provide asynchronous message buffering, EventBridge Pipes to transfer events between services, and AWS Step Functions to orchestrate the complete processing workflow.

Additionally, AWS Elemental MediaConvert will be integrated to transcode uploaded videos into HLS streaming format while continuously updating processing status within Amazon DynamoDB throughout the workflow. Processed media assets will ultimately be stored inside the Amazon S3 Processed Media Bucket, preparing the platform for global content delivery through Amazon CloudFront in the subsequent development stage.
